# Windows OCR 原生模块加载失败

`The specified module could not be found` 指向 `onnxruntime_binding.node`
时，既可能是该文件缺失，也可能是它依赖的 DLL 缺失；错误本身不指出具体缺少的 DLL。

## 现有用户恢复

1. 完全退出机器人直播控制台。
2. 从微软下载并安装 [Visual C++ x64 运行库](https://aka.ms/vs/17/release/vc_redist.x64.exe)。
   如果安装器要求重启，先重启 Windows，再打开应用。
3. 开启弹幕识别，确认不再出现原生模块错误且能实际识别文字。
4. 若仍失败，检查安装目录下
   `resources/backend/node_modules/onnxruntime-node/bin/napi-v6/win32/x64/`
   是否含有 `onnxruntime_binding.node`、`onnxruntime.dll`、`DirectML.dll`、
   `dxcompiler.dll`、`dxil.dll`。缺失时重新安装完整应用，并检查安全软件隔离记录。
   文件齐全但仍失败时，收集应用版本、Windows 版本和完整后端日志继续排查。

ONNX Runtime 官方注明 [Windows 需要 Visual C++ 运行库](https://onnxruntime.ai/docs/install/)。
仓库中运行库下载和 NSIS 安装逻辑此前均被注释，导致安装包未补齐此依赖。
这能解释干净用户环境加载失败，但不能仅据这一错误断言具体缺少哪个 DLL。

## 安装包行为与验证

Windows 构建从微软下载运行库，验证有效的 Microsoft Authenticode 签名后嵌入 NSIS。
安装时调用运行库安装器，支持离线安装；不再仅凭注册表 `Installed=1` 跳过旧版本。
退出码 0 和 1638（已有更高版本）允许继续，3010 设置重启标志，其他错误终止安装并显示
`%TEMP%\robot-live-vc-redist.log` 日志位置。

CI 检查 ONNX 原生文件及附带 DLL，并执行已有的 Electron OCR 模型推理检查。
但 Windows 构建机可能预装 VC++ 运行库，因此 CI 通过不能替代以下发布前验收：

- 在无开发工具、未预装 x64 VC++ 运行库的 Windows 10/11 虚拟机中运行安装包。
- 断网安装，批准微软运行库的 UAC 提示，确认安装成功后可实际识别弹幕文字。
- 验证取消 UAC 或运行库安装失败时有明确错误，安装器不会报告成功。
- 在已有较旧或较新运行库的机器验证升级/重复安装；按需重启后再次验证 OCR。

不要在开发机或共享 CI 上卸载系统运行库来模拟干净环境。

## 过渡音频设置与测试播报按钮

这两项不依赖 OCR。当前安装包保留 ffplay、ffmpeg、TTS 和过渡音频模块；
首次安装的过渡音频默认关闭，播报文字和素材池为空，语音凭据需用户自行配置。
升级保留已有用户内容；旧版共用的有效凭据会一次性复制到三组独立设置，之后各组独立修改。

发现并修复了一个独立的初始化时序问题：控制台 WebSocket 曾在查询处理器注册前开放。
如果首次 GET_TOUR_STATE 或 GET_TRANSIT_CONFIG 提前到达，查询会被忽略；前者让已输入文本的
测试按钮一直禁用，后者让过渡音频设置一直处于尚未加载状态。现在处理器全部注册后才监听，
且两个界面在未收到配置/状态时每两秒重试，收到回复或断开连接后停止重试。
过渡配置最多请求五次（约十秒）；持续无响应会显示超时及重新加载入口，并保留草稿。
界面显示具体禁用原因，测试播报显示后端确认、准备、播放及结束/失败状态。

ERROR 事件现在同时写入 backend.log 并在当前页面弹出，异步命令异常也会被捕获。
过渡音频的 TTS 未配置和播放失败通过同一通路上报；ffplay 保留最多 4096 字符的错误尾部。
诊断导出入口始终可见。若需要原始后台输出，在系统设置的音频诊断中勾选
“同时包含原始后台日志”；默认诊断导出不包含原始后台日志。

新增回归覆盖丢失首次查询后的恢复、按钮重新可用、播放状态、命令异常传播、过渡音频错误
以及有界播放器错误输出。打包运行时检查额外加载 Windows ntsuspend，防止 npm 可选依赖
缺失导致暂停/恢复失效。这里的原生加载检查并不替代真机音频设备和暂停/恢复验收。
