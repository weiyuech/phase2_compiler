# 知识库批量导入指南

为了简化点位管理，系统对音频和配置结构进行了重构优化。本文档将指导您如何准备 JSON 导入文件。

---

## 1. 核心设计原则 
* **音频文件与 JSON 解耦**: **JSON 文件中不包含或接收任何有关 `mp3_file` 的路径。** 
* **如何使用语音包 (MP3)**: 如果点位需要随机播放录音（1 个或多个录音），**请统一在 UI 界面中的“多音频管理”卡片中直接进行上传、删除操作。**
* **非覆盖性合并**: 批量导入 JSON 时，如果系统检测到该点位配置文件在本地已经存在，则会**自动跳过**，因此**不会抹除或覆盖已经上传到语音包文件夹中的录音文件。**

---

## 2. JSON 格式与属性说明

批量导入的 JSON 必须是一个 **JSON 数组**（由 `[` 开头，以 `]` 结尾），每个对象代表一个点位的配置。

### 字段说明：
* **`map_name`** (字符串, 必填): 地图的英文或拼音标识（例如 `"map1"`）。
* **`path_name`** (字符串, 必填): 路径的标识（例如 `"path1"`）。
* **`goal_id`** (整数, 必填): 点位数字 ID（必须为大于等于 1 的整数，例如 `3`）。
* **`goal_object`** (字符串或 `null`, 选填): 该航点对准的 COCO 目标物体类别名（例如 `"car"`、`"person"`）。如果不设置对准目标（即通用航点），**必须填写 `null`**。
* **`body`** (字符串或 `null`, 选填): 该点位的讲解词背景正文（用于大模型改写和 TTS 合成）。如果该点位仅使用本地录音播放且不需要文字，**可以填写 `null` 或留空**。

---

## 3. JSON 模板示例 (JSON Template Example)

```json
[
  {
    "map_name": "map1",
    "path_name": "path1",
    "goal_id": 1,
    "goal_object": "car",
    "body": "欢迎来到新车展示区，眼前这款车型代表了我们前沿的美学设计。"
  },
  {
    "map_name": "map1",
    "path_name": "path1",
    "goal_id": 2,
    "goal_object": null,
    "body": null
  }
]
```

### ⚠️ 注意事项：
1. 请确保所有属性名和属性值使用 **双引号 `"`** 包裹。
2. 数字类型（如 `goal_id`）和 `null` 不需要双引号。
3. 数组最后一个元素的花括号 `}` 后面**千万不要有多余的逗号**，否则会导致解析失败。
4. 如果 `body` 设为 `null`，且对应的语音包文件夹中也没有放入 `.mp3` 录音文件，当机器人抵达该航点时，系统会执行**静音抵达**（UI 显示 `[静音点位]` 并等待 1 秒后自动继续前往下一航点），不会导致巡游中断卡死。
