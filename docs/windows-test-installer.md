# Windows 测试安装包（1.1.0-test.5）

本次更新：

- 默认导出的诊断日志新增机器人连接、目标确认和导航记录，以及故障前的近期上下文；无需打开后台控制台或手动开启调试。
- 区分连接尚未建立、已建立连接关闭、未收到有效目标确认和确认内容不匹配；保留心跳时间、回复比较结果和失败阶段。本次不改变导航规则、机器人协议或等待时限。
- 机器人记录按机器隔离，隐藏原始地址及地图、路径和对象名称；日志容量受限，故障摘要单独保留。后台停止或无响应时仍可导出磁盘记录，导出前写入失败会明确标记。
- 客户安装包使用产品名称作为发布者信息，不包含个人 GitHub 仓库地址或自动更新地址。公开交付只提供安装器及对应校验和，构建溯源资料保留在内部。

继续包含此前功能与修复：

- 三机器升级保留原配置和业务数据，重新建立临时运行状态；机器 1 继承旧版，机器 2/3 首次为空、已有数据保留。用户已保存的 TTS 音频库不会清理。
- 安装器确认旧程序及后台退出后才替换；最多等待 10 秒，失败会停止升级并提示重试。无需卸载所有旧版本或手动删除缓存。
- 连续保存设置合并为单机的一次后台重启；终止失败或超时会报错，不启动第二个后台，其他两台继续运行。
- 新增“原地播报”，使用“系统设置 → 巡游讲解”的配置，支持单次、循环与停止；不移动机器人。它与巡游、手动播报互斥，切页或分屏不中断，重启不自动续播。
- Windows 交付前校验旧数据保留、实际 PCM 内容、三机并行、独立重启及安装交接；具体规则见 [三机器升级验收](three-machine-upgrade.md)。

继续包含缓存修复：

- 修复旧音频缓存占用记录阻塞机器人播报：每次运行使用独立 PCM 临时目录，旧的进程编号或残留记录不再阻止新播放。
- 缓存回收只处理已退出进程且所有权匹配的临时 PCM；其他运行实例、旧版缓存、话术、音频库和配置保持原样，无需删除用户数据。

此前三机器功能：

- 增加柔光霓虹欢迎页；只在完整启动时出现，点击或 Enter 进入机器 1。
- 一个窗口包含三个独立机器工作区，各有自己的后台、OCR worker、凭据、内容和数据。
- 机器栏可收起并通过明确的按钮展开；支持两台机器左右分屏，第三台继续在后台运行。
- 机器 1 沿用旧数据，2/3 使用 `machines/machine-2/`、`machines/machine-3/` 中的空白初始数据。
- 保存设置只重启所属机器；页面切换不销毁其他机器页面或暂停其识别和任务。
- Windows 打包增加真实 Electron 三后台、三 OCR 并发、分屏和独立重启验收。

此前功能：

- 三组设置均支持独立选择豆包、千问、DeepSeek 作为主服务商或备用服务商；备用可关闭，同一服务商不重复请求。
- 千问接入真实 API，使用完整 API Key 和模型 ID（默认 `qwen3.8-flash`）；账号数字和带星号的摘要不能作为密钥。
- DeepSeek 支持官方与火山方舟，分别保存密钥和模型，切换平台不会把另一平台的凭据发送过去。方舟使用 `DEEPSEEK_ARK_API_KEY` 和 `DEEPSEEK_ARK_MODEL`；官方沿用原配置。
- 解锁 API 密钥后，点击“使用本组豆包密钥”即可填入 DeepSeek 方舟密钥，再保存本组设置；支持已保存和刚输入的豆包密钥。
- 已实测的方舟 DeepSeek 模型为 `deepseek-v4-flash-ga-260731`；不同账号的开通状态仍以方舟控制台为准。各组可填写同一份已有方舟密钥。
- 巡游/过渡 LLM 超时会取消原 HTTP 请求，再进入备用服务商；手动播报仍直接使用第二组 TTS。

继续包含此前修复：

- 修复过渡音频设置一直等待、测试播报输入文字后仍不可点击：后端处理器注册完成后才接受界面连接，首次配置查询丢失时自动重试。
- 系统设置拆为“巡游讲解 / 过渡音频与手动播报 / 弹幕回复”三组独立凭据、模型与音色。手动测试使用第二组；允许填相同凭据，留空不再隐式借用其他组。
- 旧配置启动时按此前有效值一次性迁移，保留既有使用效果。设置按组保存，密钥与参数可一次提交；写入失败不替换原文件。
- Windows 安装器附带微软签名的 VC++ x64 运行库，用于补齐 OCR 原生依赖；安装失败会中止并显示原因。
- 操作错误同时进入界面提示与后台日志；测试播报展示准备、播放、完成或失败状态；过渡音频和播放器保留可诊断的错误信息。
- Windows 打包检查新增暂停/恢复原生依赖加载验证，并检查 ONNX 附带 DLL 的完整性。

这是与此前相同安装流程的 Windows x64 NSIS `.exe`，不是正式发布。包含准备式机器人音频、按句交接、巡游跳过/删除/暂停规则、共享过渡素材池、机器人音量调节、精简诊断 UI，以及降低截屏与识别负载并保留绿色半透明选区的 OCR 修复。

## 安装前

- 测试版沿用相同应用标识，**会替换旧版本并使用同一份用户数据，不是独立沙盒**。
- 先停止现场任务、退出应用，再备份 `%APPDATA%\robot-live-ui\`。安装器不会清空用户数据，但应用正常使用仍会更新配置和日志。
- 保留旧版安装包。需回退时先退出测试版，安装旧版，并按需要恢复备份；不要在运行中覆盖数据。
- OCR 需要 Microsoft Visual C++ v14 x64 Redistributable。本测试版已随安装器附带运行库，离线安装时也会运行；可能需要批准管理员权限或按安装器提示重启。参见 [ONNX Runtime 的 Windows 要求](https://onnxruntime.ai/docs/install/#requirements)。GitHub 托管运行器通过不等于未配置的 Windows 电脑已经通过。
- 首次安装是空巡游、空知识库、关闭且为空的过渡音频。需自行配置机器人地址、语音凭据和内容。升级不会以这些默认值覆盖已有文件。

## 构建与交付约束

1. 在本次独立分支 `codex/fix-audio-cache-instance-isolation` 提交已审查代码，排除个人设置、录音、日志、缓存和密钥；PR 检查全部通过后才打标签。
2. 测试标签必须与应用版本一致（本版为 `v1.1.0-test.5`），指向已审查的精确提交。已存在的标签/发布不得移动、覆盖或复用。
3. 标签触发 Windows 构建。PR 任务只有读取权限；只有测试标签/精确标签手动任务获得草稿交付权限。普通 `main`、PR 或正式版本标签不会创建测试发布。
4. 交付前运行后端/UI 回归、实际资源允许清单检查、打包 Electron 的 FFmpeg/Sharp/ONNX 测试，以及窗口与后端连接、端口占用兜底检查。
5. 创建新的 **draft + prerelease**，附安装包、`SHA256SUMS.txt`、`build-info.json`、`packaged-runtime.json`。脚本校验事件、标签、版本、本地提交和远端标签提交，不使用 `--clobber`。已经存在的草稿或公开发布均拒绝覆盖。
6. 下载交付资产并核对 SHA-256 后提供测试。Actions 附件上传是辅助渠道，即使其配额不足，草稿交付也必须单独成功；绿色检查本身不是可下载安装包的证明。

草稿只对拥有相应仓库权限的人员可见；标签和提交仍遵循仓库本身的可见性。本流程不合并 `main`、不更改签名配置。已获授权的客户公开下载单独交付经过校验的安装器与最小校验文件，不公开源码仓库或内部构建溯源资料。

如需给已验证的草稿补充 `streaming_app.zip`，可在 Build and Release 工作流中选择包含归档脚本的分支，
填写原测试标签并开启 `archive_only`。此任务只在 GitHub 运行器内下载和封装：校验标签提交、
成功的原构建、所有资产 SHA-256 和九项原生检查，再上传 ZIP 及其校验文件。ZIP 只放一个安装器、
原构建报告和说明，不重复放入安装器内部依赖；已有同名 ZIP 会拒绝覆盖。原应用标签和安装器保持不变。

| --- | --- |
| 全新安装 / 覆盖升级 | 新用户无开发者内容；旧用户的配置、知识库、巡游和素材关联保持；后台与前端正常连接 |
| 欢迎与多机器 | 完整启动显示欢迎页；收起/展开和双栏可操作；隐藏机器继续识别；保存机器 2 设置不重启 1/3 或重放欢迎页 |
| OCR | 开关后应用不退出；选区保留绿色半透明底色；确定、取消、重复打开正常；真实屏幕文字可识别 |
| OCR 与冷却 | 间隔 3 秒、冷却输入 10 秒归为 9 秒；原始识别日志独立更新；准备/播放跳过冷却机会；“无新问题”不生成回答；MP3 不调用 LLM |
| 本地音频 | TTS、音频文件、暂停/继续、停止/跳过、共享素材池随机/循环正常 |
| 过渡设置 | 首次查询延迟/丢失后自动恢复；断线重连后加载，未保存的草稿不被旧回复覆盖 |
| 三组凭据 | 用三组不同配置确认调用归属；手动播报与过渡共用第二组，清空任一组不串用其他组；旧版升级保持原有效配置 |
| 手动播报 | 巡游运行及暂停期间都不可测试；停止后恢复；正常取消不报错误、不推进巡游 |
| 原地播报 | 使用巡游讲解配置；单次、整段循环及停止正常；切页/分屏继续，重启不续播；不移动机器人 |
| 升级与缓存 | 不清空用户数据即可播报；旧占用记录不阻塞；保存设置时最多一个后台；机器 1/3 播放期间重启 2 不受影响 |
| 机器人 MP3 | 使用与 Python 客户端相同的文件和连接，对比连续性、音质、停止响应；不要同时运行两个发送端 |
| 机器人 TTS | 长文逐句自然衔接、克隆音色一致；准备中的高优先级音频不抢断，准备好后按当前句尾交接 |
| 优先级与场景 | 助播 → 弹幕 → 点位 → 过渡；弹幕后从下一句恢复；跳过后无旧点位残留，过渡等讲解准备好再交接 |
| 诊断 | 正常、断连、后台退出后均能从界面导出已保存的音频及机器人记录；连接失败与目标确认失败可区分，默认不含原始后台输出；不要求打开后台控制台 |

相机和推流设置未改变。同一相机/手机麦克风采集机器人扬声器时，准备延后的是开口时间，不是另一路音轨偏移；仍须检查最终录制的场景、句尾和画面同步。

机器人没有可听完成确认，因此句尾仍是发送端估计。若有明显卡顿、吞句尾、跳过后继续旧讲解或不可接受的停播延迟，保留诊断与录制，不转正式发布，不通过猜测延时掩盖问题。

## 原地播报改写与依赖验收（test.4）

原地播报使用巡游讲解的 LLM，独立保存默认/自定义提示词和可空的补充风格要求；自定义模式下补充风格置灰且不发送给模型。循环时提前一轮改写，播放和预改写同时取消，原文/改写稿切换仅用于查看。

安装验收在真实 NSIS 覆盖安装后，再用安装目录中的 Electron 执行完整原生运行检查：ONNX DLL、Sharp、两套 OCR 模型与字典、OCR 推理、FFmpeg/FFplay、Windows 暂停模块。任一失败均阻止测试版本交付。Windows 包为 x64，目标客户系统为 Windows 10/11；CI Windows runner 的通过记录不等同于每个客户硬件上的现场验收。
